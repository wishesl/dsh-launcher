# 插件市场实现方案（路线 A：启动器内置插件市场）

> 依据对 dsh-market（npm 包 `dshmarket` v1.17.1，MIT）源码的逆向研究整理，2026-08-26。
> 结论：**可行**。dsh-market 的三条核心链路（查找 / 安装 / 卸载）都可以在 Wails 启动器里以更简单的方式重实现；
> 唯一无法照搬的是"免重启热挂载"（它依赖宿主进程内部的 Cordis Include 子树），而启动器本来就管理 DSH 进程生命周期，
> 用"装卸后重启实例"替代反而更干净可靠。

---

## 1. 目标与范围

在 DSH 启动器里新增"插件市场"能力：

| 能力 | 说明 |
|---|---|
| 浏览/搜索 | 拉取社区插件目录（1500+ 条），分类筛选、关键词搜索、排序 |
| 一键安装 | 从目录条目安装到当前 profile，实时日志回显，完成后提示重启实例生效 |
| 卸载 | 二次确认后卸载已装插件并清理残留 |
| 已装管理 | 已装列表、版本展示、启用/禁用开关（免重启）、更新检查 |
| 环境引导 | pnpm 缺失时复用现有"一键安装 pnpm"流程 |

不在本期范围（记录为后续方向）：主题皮肤一键切换、备份/恢复、WebDAV/Gist 同步、按实例隔离 profile。

## 2. 原理研究结论（dsh-market 是怎么做的）

对 `~/.dsh/profiles/web/node_modules/dshmarket/src/` 的研究结论，作为本方案的依据：

### 2.1 查找链路

- 目录来源是社区 curated 注册表 **`https://awesome-dsh-plugin.com/plugins.json`**（每日由 CI 刷新），
  不是市场自己维护的列表；可用环境变量 `DSHM_REGISTRY_URL` 指向镜像。
- 抓取策略：每次打开实时抓取（无本地快照兜底——"过期的目录不是降级而是错误"），15s 超时，
  2 次重试，ETag/Last-Modified 条件请求（304 复用，实测 295KB/1.3s → 304 时 0.5s）。
- **搜索/筛选全部在浏览器端本地完成**（纯函数 `visiblePlugins()`）：关键词匹配
  `name / owner / 本地化 description`，加分类、发布时间窗口过滤和三种排序（npm 30 天下载量 > stars > 新增时间）。
- 目录条目数据结构（前端渲染与安装都靠它）：

```ts
interface RegistryPlugin {
  name: string; owner: string; url: string;      // url 形如 https://github.com/owner/repo[/tree/branch/subpath]
  category: string;
  description: { zh?: string; en?: string };
  npm?: string | null;                            // 有值 = 优先走 npm 安装
  stars?: number | null; downloads?: number | null;
  install: string; added: string;
  deprecated?: boolean; replacement?: string;
}
interface Registry { updated: string; count: number; categories: Record<string, {zh,en}>; plugins: RegistryPlugin[] }
```

### 2.2 安装链路

1. 浏览器只 POST 目录条目的 `url`；服务端重新拉目录做**白名单校验**（url 不在目录 → 拒绝）。
   这是核心安全边界：只能装社区审核过的来源，页面无法诱导服务端装任意包。
2. 目标解析 `installTargetFor()`：有合法 `npm` 字段 → 装 npm 包（优先，快且防名字抢注）；
   否则 → `github:owner/repo`，monorepo 子包 → `github:owner/repo#path:/sub`。
3. 执行方式：**重新调用宿主自己的 CLI** —— `dsh plugin --profile <p> add <target>`。
   该子命令内部就是在 profile 目录跑 `pnpm add <target>`，成功后自动执行
   `reconcilePlugins()`：把声明了 `dsh.bundle` 的新依赖追加进 profile `package.json` 的
   `dsh.profile.bundles` 层栈（loader 组合树的数据源）。**市场自己不碰 pnpm 参数细节**。
4. 防护：目标串白名单正则 `^[A-Za-z0-9@:./_#+~^=-]+$`（防 shell 注入）；重复安装守卫（别名/repo 证据识别）；
   同名冲突拒绝；pnpm ≥10 默认拦截构建脚本 → 解析 ndjson 输出得到被拦包名 → 引导用户显式放行后重试
   （写 `pnpm-workspace.yaml` 的 `allowBuilds:` 块，注意合并而非覆盖、scoped 名要加引号、保持原 CRLF）。

### 2.3 卸载链路

- `dsh plugin --profile <p> remove <name>`（pnpm remove + reconcile 自动从 bundles 层栈剔除）。
- 成功后清理三处残留：运行中组合的 loader 条目、`cordis.patch.yml` 里该插件的 disable 行、
  市场自有状态里的禁用标记/分组。

### 2.4 启停开关（不卸载）

- 写 profile 的官方补丁层 `cordis.patch.yml`：`- id: X` 行下加 `disabled: true|false`。
- DSH 的 HMR 约 1 秒内重组生效、免重启；重启后 loader 重读该文件保持选择。
- 经验教训（来自其 issue）：只对该包"自己 insert 的行"操作，不能碰它仅配置的别人的行（#147）；
  YAML 键含 `@`/冒号需引号包裹；保持文件原有换行符。

### 2.5 明确不可照搬的部分

- **热挂载**：安装后用 `@deepseek-ai/cordis-plugin-include` 把插件插进运行中的组合树——这发生在宿主进程内部，
  外部程序做不到。→ 用"装卸后重启实例"替代（见 §3 决策 D1）。
- **agent 运行检测**：市场通过宿主 agents 服务拒绝在有 agent 工作时装卸。→ 外部进程拿不到该信号，
  用更保守的策略规避（见 §3 决策 D2）。

## 3. 总体设计

```
Wails 桌面壳（Go 后端）
 ├─ market_catalog.go   目录抓取：FetchMarketCatalog（镜像/超时/重试/内存 ETag 缓存）
 ├─ market_ops.go       装卸执行：InstallPlugin / UninstallPlugin / CancelMarketOp
 │                      （白名单校验 → 目标解析 → 复用实例同款 dsh CLI 跑 plugin add/remove）
 ├─ market_installed.go 已装读取与开关：ListInstalledPlugins / TogglePlugin（cordis.patch.yml 行级编辑）
 └─ 复用：env.go(pnpm 探测+安装) · dsh_process.go(winJob 进程树管理) · settings.go(设置持久化)
          logging.go/logEvent(日志事件) · app.go/inFlight(退出等待契约)
前端 React
 ├─ MarketView.tsx        市场页（新顶层页签）：搜索栏/分类 pills/排序菜单/卡片网格/分页
 ├─ PluginCard.tsx        卡片（名称/作者/描述/星级/下载量/截图占位/安装按钮/状态徽标）
 ├─ InstallDialog.tsx     安装确认弹窗（来源展示 + 放行构建脚本引导）
 └─ api.ts / types.ts     绑定方法封装 + RegistryPlugin 等类型
```

### 关键决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | **装卸后由启动器重启实例使其生效**，不移植热挂载 | 热挂载依赖宿主进程内部 API；启动器拥有完整的进程启停能力（Job 对象杀树 + 就绪探测），重启成本 ≈ 秒级且状态确定 |
| D2 | **实例处于 running 时，装卸操作先引导停止**（一键"停止并安装"，完成后再一键拉起） | 外部无法感知 agent 是否在工作中；直接替换运行中进程读的文件会造成混合状态（dsh-market #37/#213 的教训） |
| D3 | **复用实例同款 dsh CLI 执行 plugin 子命令**，不直接操作 pnpm | `dsh plugin` 内置 bundles 层栈 reconcile；版本与实例运行的一致，避免行为漂移 |
| D4 | MVP 固定操作默认 profile `web`（`%USERPROFILE%\.dsh\profiles\web`，尊重 `DSH_HOME`） | 与 `dsh web` 启动参数一致；所有实例共享同一 profile。按实例隔离 profile 列入 M4（Instance 增加 Profile 字段 + 启动参数带 `--profile`） |
| D5 | 安装目标一律从目录白名单推导，前端不得传任意 target/url 之外的包名 | 与 dsh-market 相同的安全边界 |

## 4. 后端设计（Go）

### 4.1 新增绑定方法清单

```go
// market_catalog.go
func (a *App) FetchMarketCatalog(force bool) (*MarketCatalog, error) // 目录+分类；内存 ETag 缓存
// market_ops.go
func (a *App) InstallPlugin(instanceID, entryURL string) error       // 校验→解析→执行→流式日志
func (a *App) UninstallPlugin(instanceID, name string) error         // 同上（remove）
func (a *App) CancelMarketOp() bool                                  // 杀当前 pnpm 进程树（winJob/taskkill）
func (a *App) MarketOpRunning() bool                                 // 前端轮询互斥态
// market_installed.go
func (a *App) ListInstalledPlugins() ([]InstalledPlugin, error)      // 读 profile package.json + node_modules 版本
func (a *App) TogglePlugin(name string, enabled bool) error          // cordis.patch.yml 行级编辑
```

事件流：复用 `logEvent` 模式新增 `dsh:market-log`（行日志）、`dsh:market-status`
（`idle | running | done | failed | cancelled`），前端订阅渲染进度面板。

### 4.2 命令构造（对应现有 buildCommand 三种模式）

工作目录 = 实例目录（local 模式借此命中实例自己的 node_modules 副本），把启动命令里的 `web`
替换为 `plugin --profile web <args>`：

| PkgMgr | 启动命令（现状） | 插件命令（新增） |
|---|---|---|
| local | `npx @deepseek-ai/dsh web` | `npx @deepseek-ai/dsh plugin --profile web add <target>` |
| npx | `npx -y @deepseek-ai/dsh@<v> web` | `npx -y @deepseek-ai/dsh@<v> plugin --profile web add <target>` |
| pnpm | `pnpm dlx @deepseek-ai/dsh@<v> web` | `pnpm dlx @deepseek-ai/dsh@<v> plugin --profile web add <target>` |

要点：
- profile 尚未初始化时 `dsh plugin` 会自动初始化，无需前置处理。
- 单实例互斥：同一时刻只允许一个装卸操作（`atomic.Bool` + 前端按钮禁用），超时上限 15 分钟。
- 子进程沿用 `cmd /c` + `HideWindow` + KILL_ON_CLOSE Job 托管（复用 `newKillOnCloseJob()`），
  取消/超时时 Job 关闭即整树终止，Windows 下无需再处理 `.cmd` shim 问题。
- 环境继承系统 PATH；pnpm 缺失时返回结构化错误码，前端引导跳转现有 CheckEnvironment/InstallPnpm 流程。

### 4.3 安装目标解析与白名单（移植 `sources.ts` 的纯逻辑）

```go
// 输入：目录条目 url + npm 字段；输出：pnpm target 或拒绝
// 1. url 必须匹配 ^https://github\.com/<owner>/<repo>(/tree/<branch>/<subpath>)?$
// 2. npm 字段非空且匹配 npm 包名正则 → target = <npm>
// 3. 否则 subpath 非空 → github:<owner>/<repo>#path:/<subpath>（校验子路径无 .. / 空段）
//    否则            → github:<owner>/<repo>
// 4. 最终 target 再过一遍白名单正则 ^[A-Za-z0-9@:./_#+~^=-]+$ 才允许进入命令行
```

安装前校验顺序：目标必须在目录内 → 未安装过同名/同 repo 别名（读 profile package.json 依赖比对，
含 `#path:` 子路径身份）→ 无同名冲突。

### 4.4 allowBuilds 合并写入（顺带修复现有问题）

`install.go` 目前整体覆盖写入 `pnpm-workspace.yaml`，会把用户已有的 allowBuilds 条目清掉。
市场功能需要**合并语义**（解析既有块 → map 合并 → 回写第一处、删除多余重复块）：
- 键含 `@` 或以冒号结尾时用单引号包裹（YAML 保留字符）；
- 保持文件原 CRLF/LF 风格；
- 只添加、不删改用户已有条目；git 来源依赖的放行键形如 `<name>@git+https://github.com/<o>/<r>.git`。
- 将 `InstallToDirectory` 的写入一并切换到该合并函数（行为增强，向后兼容）。

### 4.5 cordis.patch.yml 行级编辑（Toggle）

不引入 YAML 库，按行处理（与仓库现有风格一致，且能保留注释）：
- 禁用：定位 `- id: <id>` 行（id 由已装包的 bundle patch 声明解析，或包名缺省），在其缩进层级下插入
  `disabled: true`；已存在则改值。
- 启用：移除该行的 `disabled: ...` 或改回 false。
- 保护规则：只动"该包 insert 的 id 行"；文件不存在则创建带说明头的空数组文件；保持原换行符。
- 边界：market 自身/官方 in-box 包不允许 toggle。

### 4.6 已装列表读取

- 读 `<profile>/package.json` 的 `dependencies`，过滤官方 in-box（`@deepseek-ai/dsh-base`、
  `@deepseek-ai/dsh-web-app`、`@deepseek-ai/dsh-headless`）；
- 版本取 `node_modules/<name>/package.json` 的 `version`；
- 附加 spec 类型标记（npm / github / link/file），github 类从 `pnpm-lock.yaml` 的 codeload URL 提取
  pinned commit（供 M3 更新检查对比 HEAD）。

### 4.7 目录抓取

- Go 侧 `http.Client{Timeout: 15s}`，失败重试 1 次；成功后在内存缓存 `{etag, lastModified, data}`，
  下次携带 `If-None-Match`/`If-Modified-Since`，304 直接复用。
- 镜像支持：settings.json 新增 `marketRegistryURL`（空 = 官方源），对应 dsh-market 的
  `DSHM_REGISTRY_URL` 能力。
- Go 的 `http.Transport` 默认遵循系统代理环境变量，天然优于 Node 原生 fetch（dsh-market 为此专门引入 undici）。

## 5. 前端设计（React + TS）

- 入口：顶栏新增"插件市场"页签（与实例列表同级），或 Header 加入口按钮切主视图。
- 状态：`catalog / query / category / sort / installed / opState`；搜索与筛选为纯函数
  `visiblePlugins(plugins, {category, query, lang, sort})`（移植 `visiblePlugins()` 语义：
  过滤 market 自身条目与 deprecated 标记展示 → 分类 → 时间窗 → 大小写不敏感匹配 name/owner/描述 → 排序，
  无下载量的条目排在有量之后并按 stars 兜底）。
- 卡片操作：未装 →「安装」；已装 → 「已装」徽标 + 跳转已装页；deprecated → 黄条提示 replacement。
- 安装弹窗：确认来源（GitHub repo / npm 包名）、说明"将安装到 profile web 并需重启实例生效"；
  构建脚本被拦时展示被拦包名 +「放行并重试」按钮（调用 InstallPlugin 前 Go 先写 allowBuilds）。
- 日志面板：订阅 `dsh:market-log` 实时滚动（复用 LogPanel 的渲染模式）；完成后若相关实例 running
  给出「重启实例」按钮（StopInstance → LaunchInstance）。
- 卸载：二次确认弹窗（输入包名或勾选确认），说明会清理 patch 层禁用行。

## 6. 安全设计

| 措施 | 说明 |
|---|---|
| 白名单安装 | 仅目录内条目可装；target 由服务端（Go）从目录字段推导，前端只传 `entryURL` |
| 目标串校验 | 白名单正则 + GitHub url/npm 名/子路径各自正则，杜绝 shell 元字符进入命令行 |
| 构建脚本默认拦截 | pnpm ≥10 默认行为保持；放行必须用户显式点击，逐包记录 |
| 不做遥测 | 目录抓取与 npm registry 查询之外无任何外联 |
| 官方包保护 | in-box bundles 与启动器自身依赖不可卸载/toggle |
| 操作互斥 | 全局单飞 + 15 分钟超时 + 可取消，防并发损坏 profile manifest |

## 9. 风险与限制

| 风险 | 影响 | 对策 |
|---|---|---|
| 所有实例共享 profile `web` | 一个实例装的插件其它实例也有 | 文档明示；M4 提供 per-instance profile |
| 运行中装卸的混合状态 | 正在工作的 agent 读到半新半旧文件 | D2 策略：先停后装，完成后拉起 |
| CLI 版本漂移 | npx/pnpm dlx 模式下 plugin 子命令版本 ≠ 实例运行版本 | local 模式天然一致；dlx/npx 模式建议用户固定精确版本（UI 提示） |
| 手写 cordis.patch.yml 被误伤 | 用户自定义行丢失 | 行级最小改动 + 只动本包 insert 行 + 保留注释与换行符 |
| pnpm-workspace.yaml 已有内容被覆盖 | 既有 allowBuilds 丢失 | §4.4 合并写入（随 M2 一并修复 install.go） |
| 目录源不可达（网络受限） | 市场打不开 | 镜像设置 + 明确报错与重试；不做过期快照兜底（避免"假目录"） |
| Windows 命令注入面 | 极低但存在 | 白名单正则双重校验；不经手自由文本 |
